# Nuxt 4 Fullstack Template — Design Spec

**Date:** 2026-05-17
**Status:** Approved

## Purpose

Generic reusable fullstack starter template. Nuxt 4, Feature Sliced Design, production-grade auth, type-safe API client generation, strict code quality tooling.

## Architecture

### Nuxt 4 Configuration

- `compatibilityDate: '2024-11-01'`
- `future: { compatibilityVersion: 4 }` — enables Nuxt 4 defaults
- `srcDir: 'app'` — `~` alias resolves to `./app/`
- Modules: `@nuxt/ui`, `@pinia/nuxt`, `pinia-colada-nuxt`

### FSD Layer Registration

```ts
components: [
  { path: '~/shared/ui', pathPrefix: false },
  { path: '~/widgets', pattern: '*/ui/**', pathPrefix: false },
  { path: '~/entities', pattern: '*/ui/**', pathPrefix: false },
  { path: '~/features', pattern: '*/ui/**', pathPrefix: false },
],

imports: {
  dirs: [
    '~/shared/utils',
    '~/shared/composables',
    '~/entities/*/composables',
    '~/entities/*/store',
    '~/features/*/composables',
    '~/features/*/store',
    '~/widgets/*/composables',
  ],
},
```

No root-level `/components` or `/composables` — all auto-imports come from FSD layers.

## Data Flow

### API Client (hey-api)

1. Developer writes/updates `openapi.yaml`
2. `pnpm api:generate` runs hey-api → outputs to `app/shared/api/`
3. Generated code uses pinia/colada plugin (async query hooks) + Zod plugin (response validation)
4. Consumers import from `~/shared/api` — never edit generated files directly
5. `app/shared/schemas/api.ts` holds hand-written Zod schemas for any non-generated validation

### State Management

- **Pinia stores** (`<layer>/*/store/`) — synchronous UI state: filters, preferences, UI flags
- **pinia/colada queries** (`<layer>/*/composables/`) — async server data, generated by hey-api or hand-written
- Rule: stores never call fetch directly; async data flows through pinia/colada only

### Authentication (better-auth)

- Server: `server/utils/auth.ts` initialises better-auth with all providers
- Route: `server/api/auth/[...].ts` — catch-all delegates to better-auth handler
- Client: `app/shared/composables/useAuth.ts` — wraps better-auth client
- Provider buttons rendered from config array; each provider gated by `!!runtimeConfig.providerClientId`
- Missing credentials at runtime → button hidden; no code changes needed to enable/disable providers

### Database (Prisma + Postgres)

- Prisma client singleton exported from `server/utils/db.ts`
- Schema: `User` + `Session` tables — better-auth compatible
- Migrations: `pnpm db:migrate` (`prisma migrate dev`)
- Local dev: `pnpm db:up` starts Postgres 16 via Docker Compose

## Environment Variables

`.env.example` documents all required and optional vars:

```env
# Database
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/app

# Auth
AUTH_SECRET=

# OAuth — omit to hide provider button
AUTH_GOOGLE_CLIENT_ID=
AUTH_GOOGLE_CLIENT_SECRET=
AUTH_GITHUB_CLIENT_ID=
AUTH_GITHUB_CLIENT_SECRET=

# Magic link / email
AUTH_RESEND_API_KEY=
AUTH_FROM_EMAIL=
```

## Code Quality

### ESLint

- `@antfu/eslint-config` flat config — strict TypeScript + Vue rules
- File: `eslint.config.ts`

### Git Hooks

- Husky pre-commit → lint-staged
- lint-staged: runs `eslint --fix` on `*.ts`, `*.vue`, `*.tsx` staged files

### VS Code

`.vscode/settings.json`:
```json
{
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
  },
  "eslint.useFlatConfig": true
}
```
